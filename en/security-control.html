Security and control

Letting an agent act requires separating intent, authority, reach, and evidence—because no single layer solves every problem.

Principle

Capability and risk emerge from the environment

When an agent can edit files, run code, browse, call APIs, or create persistent artifacts, the execution environment becomes part of the architecture. A correct strategy can fail because a package is missing. A dangerous strategy can “work” while crossing a security boundary.

Capability

Filesystem, shell, packages, network, browser, ports, and services.

Persistence

Mounts, snapshots, databases, files, and external side effects.

Limits

CPU, memory, time, egress, credentials, paths, and permissions.

A sandbox is an execution boundary, not the orchestrator

Separate the control plane from the execution planeKeeping session state, logs, policy, and credentials outside untrusted execution reduces what model-generated code can corrupt or exfiltrate.

Approval and containment solve different problems

Human approval preserves sensitive decisions under explicit control. Containment limits what is technically reachable even when instructions, intent checks, or review fail.

Defense in depth

Keep secrets out of untrusted execution

If generated code runs in an environment that contains long-lived credentials, prompt injection, malicious dependencies, or incorrect commands may be able to read those secrets.

  • Prefer short-lived, scoped, resource-specific tokens.
  • Use proxies or brokers that perform authorized operations without exposing the key.
  • Log usage without logging the secret.
  • Rotate and revoke independently of the sandbox.

Observations have origin, trust, and authority

Text from the web, email, issues, files, memory, skills, tools, or subagents can contain hostile instructions. Becoming tokens does not make a source trustworthy.

Stopping conditions and budgets bound autonomy

An autonomous loop can stop for different reasons: verified success, a final response, policy, human intervention, fatal error, or resource exhaustion. “Stopped” is not the same as “succeeded.”

Check your understanding

Why does human approval not replace a sandbox?

Approval decides whether an action should happen; a sandbox limits what can happen even when the wrong action is approved.

What is the strongest defense for a credential?

Keep it out of the untrusted environment. Structural reachability limits are stronger than instructions.

If the agent reaches its turn limit, is the task complete?

The loop has stopped, but the task may be incomplete. The terminal state must distinguish budget exhaustion from success.
