Interface is architecture

The model never uses “the computer” in the abstract

It uses the interface the harness exposes. One coding agent may receive read_file, search_code, apply_patch, and run_tests. Another may receive only shell(command). Both can reach the same repository, but they create very different problem surfaces.

SWE-agent called this layer the Agent-Computer Interface (ACI): the agent’s interface to the computer is an experimental variable, not a neutral implementation detail [2].

Four properties of an agent-facing tool

01 · Affordance

What can it do?

The actual capability: read, change, send, execute, retrieve, or verify.

02 · Contract

How is it requested?

Name, description, arguments, types, constraints, and preconditions.

03 · Observation

What comes back?

Data, identifiers, errors, side effects, and truncation information.

04 · Feedback

Does it help recovery?

Does the result make the next correct action easier, or force the model to guess?

Available does not mean usableAn operation may exist in the backend and still be effectively inaccessible to an agent if its name is ambiguous, its parameters are confusing, or its output hides what happened.

Tools consume attention too

Names, descriptions, parameters, and schemas enter context before a tool is ever called. The result then returns to the model and competes with the rest of the task for context.

Ctool = Cselection + Cobservation

ProblemSymptomTypical improvement
Overlapping toolssearch, find, and lookup seem equivalent.Fewer operations, clear boundaries, and namespacing.

Tool count is not a monotonic measure of capability. A new tool can expand reachable behavior while making selection harder.

A high-signal result

It answers the next decision, preserves identifiers needed for later actions, and makes gaps explicit. A payload that is elegant for conventional software may be expensive and confusing for a model.

{
  "status": "found",
  "customer_id": "cus_2481",
  "name": "Ana Souza",
  "plan": "Pro",
  "open_items": 1,
  "details_available": true
}

Errors are observations, not just exceptions

“Error” does not teach an agent how to recover. A useful error distinguishes cause, side effects, and whether retry is safe.

{
  "status": "failed",
  "reason": "branch_not_found",
  "requested_branch": "release/2.4",
  "available_branches": ["main", "release/2.3"],
  "side_effects": "none",
  "retryable": true
}

MCP is an interoperability layer, not the whole architecture

The Model Context Protocol standardizes how AI applications discover and call external capabilities. That is valuable, but it does not define the complete agent system.

MCP helps define

  • tool and resource discovery
  • request and response formats
  • capability negotiation
  • host/server integration

The harness still defines

  • loop scheduling
  • context selection
  • approval and retry
  • sandboxing and coordination
  • completion and evaluation

Active context and durable state are different surfaces

The model sees a finite window on each call. The harness decides what enters it. Instructions, the current task, tools, recent history, documentation, results, plans, memory, and subagent reports compete for the same resource.

Progressive disclosure

  1. Orient: provide enough for the agent to understand the system and task.
  2. Make discoverable: point to deeper rules, documents, and data.
  3. Load on demand: bring in detail only when the current decision needs it.

Skills are one example: reusable instructions and resources loaded when relevant. But topical relevance does not guarantee benefit. Skills can introduce functional errors, efficiency regressions, and provenance risk; they should be evaluated like any other harness component.

Compaction saves context but loses information

Replacing a long trajectory with a shorter summary reduces active-context cost, but does not preserve every detail. In general, C(H) ≠ H.

  • Preserve decisions, IDs, constraints, and explicit commitments.
  • Record where omitted detail can be recovered.
  • Separate observed facts from inferences and plans.
  • Test tasks where older details become relevant again.

Check your understanding

Why can a generic shell be worse than specialized tools?

It shifts command choice, quoting, output interpretation, and recovery onto the model. Flexibility can increase selection cost and error.

Does MCP replace the agent loop?

No. It standardizes capability interfaces. Context, scheduling, approval, execution, verification, and evaluation remain harness policies.

Why should compaction not erase durable history?

A summary is lossy; details that appear irrelevant today may become essential later.
